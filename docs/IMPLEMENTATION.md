## 窗口兼容边界

Windows 11 多标签页没有在本版声称完整支持：当 IShellWindows 返回同一个顶层窗口的多个路径时，切换会提示手动选择标签或 Shift 新开独立窗口；合并会拒绝关闭该窗口。未暴露给 Shell 的标签页无法可靠计数。跨虚拟桌面激活依赖系统策略；系统权限限制时任务栏闪烁并提示，不通过管理员权限绕过。

macOS 自动化被拒绝或超时时，读取/复用窗口不可用，UI 展示授权指引；仍尝试通过系统 `open` 打开目录。此降级路径不能保证强制新开。Mac 代码已提供，当前 Windows 环境缺少 Apple SDK/Objective-C 工具链，无法给出已编译或已验收结论。

目录别名采用本地规范化路径，大小写在 Windows 上不敏感，macOS 保留大小写以兼容大小写敏感卷。Windows 资源管理器从另一条符号链接、映射盘别名打开时，仍可能表现为另一条路径；这是跨入口身份匹配的已知限制。

## 架构与约束

前端只管理视图和编辑草稿。后端串行配置事务用 revision 防止旧配置覆盖新配置；热键和自启失败会回滚。目录校验与系统窗口操作在后台执行；工作队列有界、等待有超时。Windows COM 仅由单独的 STA 线程使用，Explorer 重启后会重连。枚举快照/可用性只在内存中保存。

收起/隐藏后可释放 WebView，唤起时在后台线程重新附加到保留的原生窗口。待处理的托盘设置、快捷键固定等意图进入有界队列，页面就绪后领取，避免重建期间丢事件。对话框打开时不回收界面。该实现启用了 Tauri 的 `unstable` 子 WebView API，因此锁定依赖并由原生生命周期测试覆盖。

没有联网命令或任意 shell 执行入口。路径作为程序参数传递；Explorer 的特殊 `/n,"path"` 格式在拒绝引号/NUL 后构造，路径不会进入命令解释器。UI 对用户别名、路径、分组和错误文本做转义，应用 CSP 限制脚本与连接来源。
